# 设置功能实现

## 当前状态

设置页已经接入 Django 后端，不再是静态表单。

## 前端实现

- `frontend/src/pages/SettingsPage.js` 未登录访问会跳转 `/login`。
- 进入页面后调用 `/api/settings/` 读取用户设置。
- 设置页改成“左侧设置导航 + 右侧内容区”的布局，借鉴系统设置页的信息组织，但保持项目现有的白底、细边框、绿色强调风格。
- 资料保存与密码修改拆成两个独立动作：
  - 保存资料时调用 `/api/settings/` 更新用户名和邮箱。
  - 修改密码时调用 `/api/auth/change-password/`。
- 密码修改成功后会清空本地登录态并跳转回登录页。
- 已从设置界面删除 `theme`、`language`、`font_size` 三个未接入前端消费链路的界面项，避免出现“能改但不生效”的假功能。
- `frontend/src/services/settingsApi.js` 封装设置读取、保存和修改密码接口。

## 后端实现

- `UserSettings` 字段：`theme`、`language`、`font_size`。
- `SettingsView` 支持 `GET /api/settings/` 和 `PATCH /api/settings/`。
- `SettingsView` 同时支持更新 Django User 的 `username` 和 `email`。
- `ChangePasswordView` 验证旧密码和两次新密码，修改成功后删除 token。

## API 接口

- `GET /api/settings/`
- `PATCH /api/settings/`
- `POST /api/auth/change-password/`

## 后续计划

- 主题设置目前只持久化到数据库，尚未全局应用到 CSS 变量。
- 头像上传模型已有 `Attachment` 基础，用户头像字段还未扩展。

## 2026-05-21 更新：用户名大小写规则对齐注册

- `PATCH /api/settings/` 的用户名占用校验已改成与注册接口一致的大小写敏感逻辑。
- 管理员修改用户资料时的用户名校验也同步复用同一规则，避免出现第二条不一致链路。
- 当前行为是：完全相同的用户名不允许复用，但仅大小写不同的用户名允许并存。
- 设置页同时移除了页头副标题、分区说明和密码提示文案，只保留必要标题、字段和值，避免无意义注释占据界面。

## 2026-05-21 更新：设置页视觉重做
